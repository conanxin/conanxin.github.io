研究网站为何需要分开正文、证据与技术日志

一则基于 2026 年 10 月 11 日实际 GitHub 提交与验收记录的方法笔记。

简介

数字研究网站不只有浏览体验，还承担保存来源、说明推断和复现技术过程的责任。Conan Xin 数字花园在 2026 年 10 月 11 日完成了跨 Agent 设计规范、四类模板和一个独立专题的兼容改造。这篇文章记录已经执行的工程事实，不把网页排版或 CI 通过当作学术结论已经得到证实。

正文

第一层是正文：让读者知道这篇文章试图回答什么、为什么重要，以及哪些内容属于作者的解释。第二层是证据：把可核查的文献、网页、提交记录与对应说法放在一起，避免将系统运行结果直接当作历史事实。第三层是技术记录：只记录构建方式、变更范围和测试结果，让未来的自己或其他 Agent 既能复现页面，也能辨别研究解释与工程验证的边界。三个层次应当相互链接，但不互相替代。

设计约束之一：不改动已有研究数据、引文、文章正文、专业交互与图像。保留研究资产，比追求一次性全站统一更重要。

2026 年 10 月的具体做法是：以 assets/site/design.css 为视觉 token 来源，以 scripts/build_site.py 为发布时共享导航与样式的注入点，以 templates/site/ 提供文章、项目、展览和文献四类页面骨架。SpaceX 火星长文原本拥有独立的深空与火星沙阅读界面，Stage 2B 因而没有删除其本地设计，而是把唯一专题入口从全站强制样式中隔离，并保留品牌、无障碍与身份规范化。有关实际开发步骤见 网站设计工程档案。

证据

证据 1 · PR #10 / #11 · 规范与模板

PR #10 建立跨 Agent 的设计规范入口；PR #11 提交四类完整 HTML 模板、模板发布排除和公开 设计样板页。这些是可独立查验的代码与合并记录。

证据 2 · PR #12 · 原生专题兼容与发布

PR #12 保留火星专题独立主题，增加移动端长网址自动断行和双视口回归检测。合并提交为 3e3c929；正式发布的 GitHub Actions Run 显示构建与公开读者页面验证通过。工程验收并不能独立验证历史材料的可靠性。
