From Catalogue to Research Infrastructure

一份在 Shuge.org 上浏览的书目列表，如何变成可检索、可引证、可治理的研究基础设施？

这个展厅讲述的是项目方法论本身 — 不是一个研究问题，而是「做研究的装置」本身的设计。

九个里程碑

本项目从一份公开的数字古籍目录（Shuge.org）出发，经历九个阶段。每个阶段都有明确的产出与可验证的 acceptance gate。

研究基础设施的六个层次

1. 采集Acquisition · 从公开数据源下载 PDF + 元数据 · JDA + BnF Gallica + Shuge.org
2. 消化Ingestion · PDF → 图像 → OCR 文本 → FTS5 索引 · 833,202 chars · 3,553 pages
3. 检索Retrieval · 中文分词 + 引用合成 + claim 抽取 · research_search.py + research.py
4. 治理Governance · 集合定义 + 快照 + 审计 · 283 memberships rebuild 幂等
5. 策展Curation · thematic collection · 历史水利/建筑营造 · verified-false 标注
6. 展示Exhibition · 静态 JSON + 数字博物馆 × 学术实验室风格 · v0.1 / v0.2

Take-away
「研究基础设施」≠ 一个数据库。它包含采集、消化、检索、治理、策展、展示六个层次，每一层都需要单独的纪律。本项目把这六个层次分别物化为 GitHub Issues（P1-P5-D + Exh）以保持纪律的可追溯性。
