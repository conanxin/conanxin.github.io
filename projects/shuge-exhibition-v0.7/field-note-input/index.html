Manual Method · 5-Step Workflow

  1. Step 1: Fieldworker drafts note in Markdown with YAML frontmatter matching this schema.
  2. Step 2: Fieldworker or curator commits note to /data/field_notes/incoming/ folder.
  3. Step 3: Pipeline script (P5-E only) validates schema, validates place_id, validates citation_ids.
  4. Step 4: On success, note moves to /data/field_notes.json and gets linked to workspace + research_questions.
  5. Step 5: v0.6+ site rebuilds; note appears on /field-notes/ page.

Validation Rules · 7

  1. Unique ID: field_note_id must be globally unique across all field_notes.json records.
  2. Valid Place: place_id must exist in places.json (canonical, no place- prefix).
  3. Citation Format: all linked_citation_ids must match SHUGE:p<post_id>:<page_seq> format and exist in citations.json.
  4. Optional IDs: linked_evidence_card_ids and research_question_ids are optional, but if present must exist.
  5. Enum Status: verification_status must be one of 4 enum values (UNVERIFIED / VERIFIED / CONTRADICTED / NEEDS_REVIEW).
  6. Photo Count: photos_count must be integer ≥0; actual photos not stored in v0.6.
  7. WGS84 Range: gps_lat/gps_lng must be valid WGS84 lat/lng range if provided.
